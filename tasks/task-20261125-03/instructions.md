# 任务记录 task-20261125-03：clip range 的加记录重训（事后分析）

记录时间：2026-11-25 03:41（Asia/Shanghai）

## 用户要求

用户原话：“加记录重训。也同时看看 clip range 的放宽是否会导致梯度裁剪更频繁”

背景（上一轮对话）：3.6.4 节发现“clip_fraction 只有约 9%，但每轮改动幅度几乎跟着 clip range 成比例变化”，当时的解释没有验证。用户提议：看被裁掉的那部分数据的梯度对整体梯度的影响有多大，以及不同 clip range 和梯度方差之间的关系。我提出了两个方案：加记录重训，以及从同一存档出发的受控重放。用户选择了加记录重训，并追加了一个问题：放宽 clip range 是否会让梯度范数裁剪（max_grad_norm = 0.5）更频繁。

## 要做的

1. 不改变训练本身，在每次小批更新时记录：
   - 被裁剪数据的拆分：SB3 的 `clip_fraction`（越过边界的全部数据）、真正被置零梯度的数据（往有利方向越界）、往不利方向越界的数据；
   - 反事实梯度：带裁剪的梯度 g_c、去掉裁剪的梯度 g_u、被置零数据本来会贡献的梯度 g_z = g_u − g_c；
   - 梯度在小批之间的一致性（方差），分别对 g_c 和 g_u 计算；
   - 参数实际走的路径长度和净位移、相邻两步的方向余弦；
   - 梯度范数裁剪：每步的总范数、策略网络和价值网络各自的范数、是否触发；以及“如果不裁剪”时是否会触发（反事实）；
   - 每一遍结束时在整批 2,048 条数据上的真实 KL，以及概率比相对边界的分布。
2. 配置：clip range 0.05、0.1、0.2（基线）、0.3、0.5；另加 epochs = 1、3，用来得到每轮结束时真实的 KL（3.6 节里这两行的 approx_kl 加了括号）。种子 0–2。
3. 验证记录不影响训练：同种子重跑的 progress.csv 和最终评估应与 `runs/ablation/` 中原来的结果逐位相同。
4. 分析，回答：被裁掉的数据对梯度影响多大；clip range 与梯度方差的关系；更新是否停在边界附近；放宽 clip range 是否让梯度范数裁剪更频繁。
